# 学生中心：分群支持与个体跟进

2026-10-04。当前只核对规则与范围，不修改正式前端。

## 已核对的实现

- 正式 StudentCenter 页面由 TeachingPortal 展示学生名单、个人任务与教学报告；studentCenter.js 的完整成长与证据模型当前主要服务演示数据。
- teaching.students 返回 JOINED 成员关系，每行含 student id、姓名、账号、classId/className。同一学生可能返回多行。
- 任务分配包含 completionStatus、validCount、effectiveDeadline、extraAttempts、exempt、overrideReason、canStart/受阻原因，以及 attempts 的状态、有效标记、提交时间、失败原因和报告ID。具体字段应以上线响应校验为准。
- teaching.report 返回评分、训练上下文、回答及点评；教师访问受报告授权约束。不能由成员关系推导出所有自主训练的查看权。
- 现有接口支持任务创建、发布、任务未完成人群提醒、补充分配、个人补练/截止/减免、报告重试和点评。
- 没有确认可用的独立学生跟进记录、复核日期、处理状态接口。首版不提供虚假的“标记已解决”，也不将浏览器存储用作正式跟进记录。

## 数据归一与范围

1. 人员主键为 studentId（students 接口为 id）。同学生合并一行，并保留 classes[] 成员关系，筛选班级后再计算该范围证据。
2. 一项分配以 assignmentId 唯一，一次尝试以 attempt/session ID 唯一，报告以 reportId 去重。学生人数、任务分配数、有效尝试数分别计算。
3. 默认当前已加入成员，历史被移出成员不自动进入当前分群；历史授权报告保留在关联任务中查看。
4. 所有训练指标限定教师授权的教学记录。时间使用 Asia/Shanghai；统计周期内的记录与当前未完成任务分开展示。
5. 岗位字段表示教学训练岗位，不冒充个人求职目标。账号状态需成员接口补充核对；失效账号不能作为新任务接收者。
6. 跨班可分析去重人群，但创建训练按 classId/jobId 分组。一个学生加入多个班级时需明确目标班级，避免对同一人重复发放。

## 首版分群规则

规则透明显示在页面，标签为当前支持需求，可重叠、可随证据变化，不作为永久评价。

| 人群 | 判断条件 | 排除/不足情况 | 解决入口 |
| --- | --- | --- | --- |
| 尚未开始 | 至少一项已开放、未结束、未归档、未减免分配，且尚无尝试 | 未来开始任务不计；已尝试但无有效结果属于其他执行状态 | 定位分配，核对任务后进入提醒/截止调整 |
| 执行受阻 | 活跃分配存在报告FAILED、次数耗尽或明确不可开始原因 | GENERATING是等待生成，不直接视为失败；技术失败与无效提交分别显示 | 查看失败依据；报告重试、个人补练或任务处理 |
| 逾期需核查 | 已发布有效分配超过个人优先截止，未完成且未减免 | 手动结束/归档不混入当前可处理逾期；无截止数据不推断 | 查看任务与个人截止，核查原因后调整 |
| 共同能力短板 | 同岗位、同维度、可比版本最近有效分数距实际目标至少10分 | 未知目标/版本或缺失评分不进入；10分只是明确显示的首版分组规则 | 查看报告，勾选共同问题学生，按班级创建草稿 |
| 已有投入仍有短板 | 所选周期、岗位至少3次有效训练，且当前所选维度低于真实目标 | 3次为可调整分析筛选门槛，不代表努力程度或风险；不可跨岗位合计 | 核查回答与反馈，调整训练内容或针对性点评 |
| 表现下降待核查 | 复用growthFor/真实studentGrowth：至少6条连续同岗位同版本有效记录；最近3次连续下降且首尾下降至少5分 | 岗位/版本切换重启阶段；完整评分不足显示数据不足 | 查看6条记录、变化维度与原报告，不自动归因 |
| 接近/达到目标 | 所选维度距目标不足10分且未达到，或分数达到实际目标 | 维度达标不等于所有能力达标 | 巩固或进阶任务建议，由教师确认内容 |
| 证据待补齐 | 未评分、评分口径不可比、报告仍生成或读取失败 | 必须分别说明具体状态；读取失败不计作未评分 | 重试读取、查看任务与覆盖、等待报告 |

人群柱状图展示去重人数，但不同柱可重叠；“需支持总人数”按学生集合并集计算。名单同时显示多个命中原因，不把最高优先级原因当作唯一问题。

## 支持操作边界

| 操作 | 已有支持 | 首版实现安排 |
| --- | --- | --- |
| 指定学生创建训练 | createTask + 指定接收者，班级洞察已有预填 | 复用classId/studentIds/abilityCode/returnTo；跨班先选目标班级或逐组核对草稿，不自动发布 |
| 补充分配 | supplement(taskId,studentIds,reason) | 跳转相关任务，选择有效成员并保留原因 |
| 个人补练、截止或减免 | override(taskId,assignmentId,reason,...) | 定位个人分配，复用现有表单，不在学生中心复制规则 |
| 报告生成重试 | retry(sessionId) | 按授权与允许状态处理；不得将无效回答通过重试变为有效训练 |
| 点评与反馈 | review(reportId,text) | 查看原报告并点评；不把点评当作独立跟进状态 |
| 批量提醒所选学生 | remind(taskId)只针对任务未完成且未减免的人群 | 首版跳转任务提醒并展示实际接收范围，不能宣称支持任意勾选学生提醒 |
| 独立跟进计划 | 未确认接口 | 二期需要跟进表、权限、操作记录和复核规则；首版不模拟正式保存 |
| 支持后变化 | 已有报告与任务调整数据 | 展示可比评分与执行变化；不声称因果效果或“问题已解决” |

## 图表与页面范围

### 支持工作台

标题 → 班级/周期/教学岗位/维度/姓名搜索 → 支持需求人数横向柱状图 → 所选人群规则与证据摘要 → 对应分析图 → 去重学生名单。

首屏以分群柱状图为主；能力短板人群显示目标差距分布柱；投入人群显示有效次数×所选能力散点；执行受阻人群优先清晰的原因与分配清单，不硬加能力图。图表点击等价于文字筛选，便于键盘与手机使用。

### 个体问题档案

简洁身份摘要和班级关系 → 当前支持需求与命中原因 → 可比多次训练维度柱 → 相关回答/报告证据 → 当前任务与个人调整 → 后续可比变化。

数字不加悬停下划线，证据用正式按钮；选中用淡绿背景与边框。列表分页、筛选与返回状态保持一致。

### 联动

- 班级洞察 → 学生中心：classId/jobId/abilityCode/人群条件/returnTo，学生中心显示来源范围。
- 学生中心 → 班级洞察：指定班级与能力维度，不把跨班混合人群直接塞进单班页面。
- 学生中心 → 任务：classId/taskId/assignmentId/returnTo，核对当前成员、归档状态与任务可操作性。
- 学生中心 → 报告：reportId/returnTo，权限失败提供返回与恢复入口。
- 创建草稿后仍由教师核对参与名单、岗位、题目和完整评分方案，再发布。

## 质量与加载要求

先取成员、任务与分配，按当前人群需要加载评分与点评；报告ID去重、限制并发、保留部分失败信息。不能因一次评分失败把该学生归为“无评分”。

验证：同学生跨班合并、班级筛选后证据隔离、任务未开放、免除、个人截止、生成中/失败/无效区别、未知版本、少于6条成长记录、跨班草稿接收范围、来源返回及360/390/1440宽度。

## 下一步交付

独立视觉评审稿先完成三条路径：

1. 支持工作台 → 共同能力短板 → 核查报告 → 按班级安排训练草稿。
2. 执行受阻人群 → 明确失败/次数受限原因 → 原任务的个人补练入口。
3. 个人问题档案 → 多次评分与回答依据 → 当前安排与后续变化。

补齐跨班学生、无评分、样本不足、部分读取失败、无匹配人群等状态；示例数据明确标注，不写入正式业务接口。
