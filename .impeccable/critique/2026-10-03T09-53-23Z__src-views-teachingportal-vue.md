可以进入下一阶段。我的建议是重做教师端的页面组织和交互，保留现有真实教学数据与业务规则，按“修正口径与联动 → 重做任务工作台 → 重做总览与分析 → 清理旧展示”的顺序实施。本轮完成了独立评审，没有修改业务代码。

**对当前设计的判断**

教师端已经有教学业务基础，但页面仍以管理表格和统计容器为中心，没有充分围绕“发现哪些学生需要帮助、查看依据、安排下一次训练”组织。学生端的下一步训练、原因和操作更集中；教师端让用户自己在多个页面拼接判断。这是目前最值得重做的部分。

需要纠正此前的判断：总览和数据分析现在已经使用不同组件，并非完全相同；图表也不是全部没有数据。有些空白是评分方案不一致或样本不足造成的合理限制。仅增加图表数量不能修复这些问题。

**设计健康度：24/40，需要明显改进。**这是专家评审分数，不是用户满意度调查。

| 评估项 | 分数 /4 | 主要依据 |
|---|---:|---|
| 系统状态可见 | 3 | 有任务与报告状态，部分报告读取失败却没有明显提示 |
| 贴近真实教学 | 3 | 有效次数、补练等规则明确，“成长”入口仍不符合名称 |
| 用户控制与返回 | 3 | 有返回与清筛选路径，跨页范围保留不完整 |

应保留三个优点：真实数据不足时没有制造能力提升；任务评分约束、个人截止时间和有效次数已有业务基础；原始回答、报告与教师点评可以成为判断依据。重做应建立在这些基础上。

**五项优先问题**

1. **[P1] 报告结论与作答证据矛盾。**实测报告68为无效训练、0道主问题作答，却出现“完成全部主问题”的优势，同一能力还同时被描述为突出和薄弱。这份报告不能支持能力判断。前端应先展示“未形成可评价回答”，隐藏不成立的能力结论；生成端也要修复兜底评价。保留原始问题与过程证据，不把未作答等同于能力差。对应工作：`impeccable clarify / harden`。

2. **[P1] 页面承诺的范围和去向不成立。**总览选定一个班级后进入学生名单，地址仍带班级ID，但显示全部19人；“4条逾期未完成”进入任务页后仍显示全部9项任务；“查看成长情况”实际进入训练记录。必须统一班级、任务、时间、岗位和评分方案的筛选上下文，让目标页面真正消费筛选；成长功能完成前将入口改为“查看训练记录”。对应工作：`impeccable clarify / harden`。

3. **[P1] 教师看见问题后仍要自己找人处理。**真实任务表缺少完成进度、逾期人数和有效次数分布，待办也没有直接定位学生分配。应以学生任务分配为单位建立“逾期待处理、待点评、异常报告、申请处理”队列，直接打开名单、报告和可用操作。提醒、补练、延期遵循现有权限与规则；跨任务批量操作需要后端明确结果，不能把逐条调用伪装成一次原子操作。对应工作：`impeccable layout / clarify`。

4. **[P2] 任务创建把配置负担一次交给教师。**未选班级已有23个输入控件，选择班级后还增加学生选择；手机长页约3023px，保存按钮在底部。建议分成“对象与时间 → 题目与评分 → 完成要求 → 确认发布”，提供合理默认值、可编辑题目列表和持续可见的摘要，高级设置折叠。保留已有“保存草稿→查看详情→发布”业务流程。对应工作：`impeccable onboard / distill`。

5. **[P2] 图表层级、空态与读取方式需要整体整理。**总览六个同权指标、待办靠后；分析缺样本仍保留大幅空坐标；动态页混用报告周期、当前任务和全局待办。每图需紧邻显示范围、样本量和口径，空态提供原因及下一步。实测总览/分析首次加载36个API响应，其中23份报告逐份读取；筛选变化还会重新加载。应改成摘要聚合与按需读取，并区分“无数据、不可比较、读取失败”。这次没有测到超时，36次请求体现的是扩展成本。对应工作：`impeccable layout / optimize / harden`。

**新的页面职责**

| 页面 | 核心问题 | 布局与行动 |
|---|---|---|
| 教学总览 | 今天先处理什么？ | 3—4个核心指标、置顶待办、任务进度排行、简洁参与趋势；进入具体任务或学生名单 |
| 班级中心 | 哪个班、哪些学生需要跟进？ | 班级列表、成员管理、任务覆盖与参与；邀请成员、查看需关注名单 |
| 训练任务 | 这项任务推进到哪里？ | 搜索与状态筛选、每项完成分子/分母、逾期及待点评数量；进入任务督导工作台 |
| 学生中心 | 这个学生的问题与下一步是什么？ | 任务履约、可比较的能力记录、原始回答和教师反馈；安排补练或点评 |
| 数据分析 | 一个时期内教学效果如何？ | 覆盖、执行、结果、能力四类分析；明确分组和排除原因，联动到原始记录 |

任务工作台应成为第一块重做样板：顶部固定显示任务、班级、时间和评分方案；中间展示执行图表；下方是与图表联动的学生名单和处理入口。教师点击“未完成”后看到的必须就是这一任务的未完成人员。

**多图表如何传达信息**

| 图表 | 建议位置与表达 | 交互与口径 |
|---|---|---|
| 柱状图 | 总览比较各任务完成进度；任务页展示次数分布 | 明示分子/分母；点击定位对应任务或学生组 |
| 折线图 | 训练参与随时间变化 | 每个折点显示日期、人数/次数及有效性；人数与次数区分单位 |
| 环形图 | 单项任务的人员状态组成 | 状态互斥且完整；扇面显示人数和占比，并筛选名单 |
| 堆叠条形图 | 比较班级或任务的执行构成 | 使用一致状态定义；同时展示总人数，避免仅看百分比 |
| 散点图 | 分析训练投入与学习结果的关系 | 明确横纵轴；仅使用有意义且可比较的样本；点击进入学生证据 |
| 直方图 | 看有效次数或同方案成绩分布 | 明确分箱与样本量；区间点击进入学生组 |
| 箱线图 | 比较班级的同方案成绩分布 | 样本不足不显示；解释中位数、区间与异常值 |
| 能力条形图 | 个人或同方案群体的模块表现 | 显示选用维度、目标、权重与版本；不同方案分组查看 |
| 热力图 | 识别班级×能力模块的薄弱区域 | 缺数据采用独立标记；点击单元格查看可比样本与报告 |

图表选择应围绕变化、比较、组成、分布和关系，而非给每页塞满所有类型。[Tableau官方图表选择说明](https://help.tableau.com/current/pro/desktop/en-us/what_chart_example.htm)同样按问题和数据结构区分这些用途。散点不能据此宣称因果，环形图不能混合重叠状态。

学生自选评分维度必须在教师端显式体现：任务结果按任务发布时冻结的方案判断；自主训练保留自己的方案；能力比较按岗位、维度、目标、权重及版本分组。不同方案的总分不得直接混算，不可比较不等于低能力。缺少历史版本信息的报告只能作为原始记录查看，不能靠前端补造版本。

**保留、删除和重做**

| 处理 | 内容 |
|---|---|
| 保留 | 真实实体ID、权限、任务草稿/发布、个人截止与补练、报告原始证据、点评、消息联动及演示参考 |
| 删除或合并 | 重复指标、无行为的展示入口、无意义彩色圆点、空坐标占位、同一页反复出现的缺数据说明 |
| 替换 | 真实版的大表格和长表单，改成任务进度、可处理队列、分阶段配置与聚焦详情 |
| 最后清理 | 已有真实替代并核对路由后，再删除旧页面和重复组件；仍可达的页面不能直接删除 |

视觉沿用学生端白灰、翠绿、清晰边界和字号层级，教师端采用更适合比较与批量操作的密度。统一筛选条、表格、图表、空态、详情和消息组件；图表需具备悬停数值、键盘操作与可读数据表。颜色用于区分数据，主要操作仍保持品牌翠绿。不要用装饰图标补救层级不清。

**使用负担与小问题**

- 新教师：创建任务同时面对题目、五组评分配置和次数规则，缺少分阶段引导；“成长”与“模板”的名称不对应真实落点。
- 多班级教师：班级筛选跨页失效、逾期队列不聚焦，导致重复找人；这是主要效率瓶颈。
- 键盘或低视力用户：图表组件的交互与数据表支持不统一，小折点和近似绿色曲线不易辨认。已有部分支持应复用，仍需专门验证屏幕阅读器与缩放。

当前负担来自同权指标、长配置、跨页记忆和复杂性一次展开。首次观看较平静，点击后范围改变、报告出现矛盾时形成明显信任落差。还需处理“—人”等单位拼接、过小图例，以及缺少学生/任务信息的重复消息标题。手机实测没有整页横向溢出，但纵向信息负担较重。

**实施顺序与验收**

1. 修复报告有效性、跨页筛选和返回路径。验收：选定范围往返不丢失，无作答不生成能力判断。
2. 重做任务列表、创建流程和督导工作台。验收：点击图表进入准确名单，提醒、补练、点评形成可验证的教师与学生联动。
3. 重做总览、班级、学生中心和分析。验收：总览服务当下处理，分析服务周期判断；每图有明确口径、范围、样本量和证据入口。
4. 统一组件、聚合读取并清理旧展示。验收：真实数据、空数据、读取失败都可理解和恢复；演示与真实版使用同一套页面结构。

值得确定的两个设计取舍：第一块样板优先任务督导还是总览；教师端采用更高密度的工作台还是更接近学生端的宽松卡片。建议任务督导优先，采用清晰但适度紧凑的工作台。

**证据边界**

本轮使用两个独立评审、真实账户与空账户、桌面和390px手机浏览器核查。七个Vue文件的CLI规则扫描为0项，不能替代交互核查；三页运行态检测分别给出1/4/9个信号，统一中文字体的提示属于误报，不代表缺少层级。模拟报告读取失败暴露了恢复入口不足。未提交任务发布等写操作，未做千份报告压力测试、200%缩放或屏幕阅读器验证，因此不声称这些流程已经通过验收。
