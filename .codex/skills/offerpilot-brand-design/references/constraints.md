# OfferPilot visual constraints

## Source precedence

1. The current user request.
2. `PRODUCT.md` product truth and commitments.
3. `DESIGN.md` current mobile visual direction.
4. Shipped UI and tokens for the target surface.
5. `DESIGN-SYSTEM.md` as legacy/reference material where it does not conflict.

The repository currently contains tension between a calm warm-white/forest-green mobile direction and an older blue/cyan cyber/glass direction. Do not blend them by default. For current mobile work, the calm direction wins; for untouched desktop surfaces, preserve behavior and ask before replacing the visual world.

## Desired character

- Practical, warm, credible, focused
- Encouraging action without hype
- Quietly distinctive rather than futuristic
- Suitable for students and early-career users without feeling childish

## Anti-patterns

- Generic AI startup imagery and copy
- Neon technology spectacle, glowing particles, unexplained gradients
- Excessive glassmorphism or nested cards
- Inter as an automatic choice instead of a reasoned typography decision
- Icons as the only semantic carrier
- Fabricated proof or performance promises

## Existing logo evidence

Current assets use a green, rounded stroke-built rising form. This is incumbent evidence only. Do not silently preserve, replace, or reinterpret it during unrelated work. A future redesign must begin from a fresh brief and compare against the incumbent in neutral black-and-white tests.
