# 学生教学任务与教师分析联动实施记录

更新：2026-10-03。

## 已落实

- 学生任务列表采用有明确边界的任务卡片，支持班级、进度、标题筛选。任务详情分开呈现要求、有效次数、剩余机会、截止安排、评分方案、训练记录与教师反馈；补齐无数据、加载失败、报告失败重试和无法开始的原因。桌面与 360px 手机均可使用。
- 教师草稿可配置五个评分维度、优先级和目标；发布后冻结。教学训练由服务端使用教师方案，自主训练保留学生自选方案。会话保存任务与评分快照，两端报告展示同一组原始分、权重、目标和配置来源。
- 综合匹配度只计算报告实际选中的五项，缺失分数不能冒充零分，真实零分保留。有效训练完成次数与能力达标分别表达。
- 教师分析支持指定任务，指标、折线、扇形、散点和记录共享范围。散点纵轴按有效次数要求进度计算；全任务范围取消缺乏共同标准的分部评价。打开报告、学生后返回保留筛选上下文。
- 教师可补充分配晚加入学生、增加个人次数、设置个人延期或减免，并记录原因。减免不进入完成率分母，既有有效训练和报告仍保留。
- 两端区分自主训练与教学任务，训练历史提供来源筛选。教学记录不允许学生删除；报告访问继续由后端校验归属。
- 新增表采用增量建表，保留历史评分。旧报告没有评分目标或版本时明确缺失，不填默认目标、不重算历史结果。

## 接口与主要入口

- 教师创建/编辑任务：`scoreModules`；任务详情返回 `scorePlan`。
- 补充分配：`POST /api/teaching/tasks/{taskId}/supplement`。
- 个人安排：`PUT /api/teaching/tasks/{taskId}/assignments/{assignmentId}`。
- 学生分配详情：`effectiveMaxAttempts`、`effectiveDeadline`、`exempt`、`startEligibility`。
- 报告：`trainingContext` 包含来源、任务快照、评分方案和生成规则版本。
- 学生训练记录：`trainingSource`、`taskTitle`、`assignmentId`、`reportState`。

数据库变更位于 `后端/src/main/resources/db/teaching_alignment.sql`，由现有启动迁移执行。教师方案、训练快照、评分来源、个人安排、变更记录分别存储。

## 当前边界

本轮采用教师统一评分模式，没有开放“部分教师固定、部分学生自选”的混合模式。不同版本和不同方案的能力评分仍按单报告查看，不开放容易误读的跨版本均分、排名或成长结论。历史报告没有足够版本信息时标为旧版，既有分数不追溯修改。历史时间点的成员/分配复原统计不在本轮实现范围，当前完成率明确按现有任务分配计算。
