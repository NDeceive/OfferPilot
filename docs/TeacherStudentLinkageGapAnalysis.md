# 学生端与教师端联动缺口及实施建议

2026-10-03，基于当前仓库路由、前端服务、后端 Controller/Service/Entity 的静态检查。本次只分析，不修改业务实现。

> 后续实施已完成班级、任务执行、报告反馈与消息闭环。本文保留为实施前审计记录，最新状态见 `TeacherStudentLinkageImplementation.md`，下列缺口不代表全部仍未解决。

## 当前事实

教师端已完成内部演示数据联动，发布、延期、点评仍存于浏览器 localStorage。学生端有真实自主面试、本人训练记录及报告能力，但没有班级加入、教师任务接收、分配任务执行或教师反馈消费流程。因此“教师端页面互通”不等于“两端真实业务互通”。

证据：

- `前端/src/router/index.js`：教师有班级查询和成员管理路由，无创建班级流程；学生无班级、教学任务或消息路由。
- `前端/src/services/teacherRoster.js`：班级目录为固定演示种子，成员变更保存在本机。
- `前端/src/services/trainingTasks.js`、`teacherData.js`：任务和点评保存在本机，非跨账号服务。
- `后端/src/main/java/com/zhimian/dto/StartInterviewRequest.java`：开始面试没有 taskId/assignmentId。
- `后端/src/main/java/com/zhimian/entity/InterviewSession.java`：现有会话没有教学任务分配关联。
- `后端/src/main/java/com/zhimian/controller/ReportController.java`、`service/ReportService.java`：报告仅本人访问，没有教师授权读取和点评接口。
- `后端/src/main/java/com/zhimian/service/TeacherDashboardService.java`：教师总览查询全平台学生和会话，不按任课班级范围隔离。
- `后端/src/main/java/com/zhimian/service/InterviewFlowService.java`：删除本人会话会同时删除关联报告、维度、追问和消息；接入教学任务后须补保留规则。
- `前端/src/services/learningResources.js`：编程专项训练为本机演示检查，不能直接算真实有效任务完成。

## 必须补齐的业务能力

| 链路 | 教师端 | 学生端 | 共享服务 |
|---|---|---|---|
| 建立班级 | 创建班级、基础资料编辑、邀请入口 | 我的班级、查看教师与成员关系状态 | 班级、任课教师和学期关系 |
| 确认成员 | 邀请码管理、申请审核、按已有账号匹配导入 | 输入邀请码、确认班级、查看加入结果 | 成员状态、唯一关系、申请与审核记录 |
| 分配任务 | 将现有创建、发布、延期、结束操作接真实接口 | 我的教学任务、任务详情、截止及次数要求 | 任务配置快照、逐学生分配记录 |
| 执行训练 | 读取实际训练进度和尝试结果 | 从任务开始、继续训练、提交结果 | 分配→尝试→会话关联；服务端校验规则 |
| 生成报告 | 授权查看完整报告及问答证据 | 查看本次任务结果、报告生成与失败重试 | 原始问答、报告状态、评分模型与版本 |
| 点评反馈 | 保存和发布点评、查看送达状态 | 在报告内查看教师点评及再次训练入口 | 点评历史、发布状态、学生可见范围 |
| 消息触达 | 提醒未完成学生、记录提醒对象 | 首页待完成提示、站内任务/点评消息 | 消息投递、已读、去重、真实业务链接 |
| 统计权限 | 所带班级、学生、任务及能力分析 | 本人任务进度与成长记录 | 相同记录、口径、版本与服务端权限 |

建议“我的班级”先放在学生个人中心，“教学任务”在首页增加醒目入口并进入任务列表，教师点评直接嵌入现有报告。复用现有面试、历史和报告页面，不另建整套平行训练系统。桌面端与移动端均补这些入口。

## 数据关系与权限

最小业务关系：班级→任课教师/成员→任务→学生分配→训练尝试→会话/训练记录→报告→教师点评。

真实 studentId 使用用户账号 ID，学号和姓名用于展示及校验，不作为主键。demo 的 ci-* 身份仅留在演示命名空间，不按名单序号映射真实账号。学生可加入多个教学班，应使用独立成员关系；任务归属班级，成员变更不覆盖历史任务分配。

新增核心实体建议：班级、教师班级关系、学生成员关系、训练任务、任务分配、训练尝试、教师点评、站内消息。复用现有账号、面试会话、问答和报告表；为会话/记录补来源、assignmentId、attemptId 和配置快照关联。

教师只访问有授权关系的班级、学生和报告。学生只访问本人分配及已发布给本人的点评。加入班级不默认开放全部个人历史报告与简历；第一版默认开放该班级任务报告，个人自主训练按明确授权范围共享。上述规则在服务端执行，不能只靠路由或前端筛选。

公开注册继续创建学生账号；教师账号由管理员授予或邀请激活。管理员账号管理可后续完善，不允许公开注册自行选择教师身份。

## 状态与结果必须分开

- 任务生命周期：草稿、待开始、进行中、已结束；自然截止与手动结束保留不同原因。
- 学生执行：未开始、训练中、待校验、已完成；完成按服务端判定的最低有效尝试次数计算。
- 截止事实：是否逾期、是否逾期提交，从有效截止时间和提交时间计算，不用报告生成时间判定。
- 报告状态：未生成、生成中、已生成、失败；失败重试不重复计训练次数。
- 点评状态：未点评、已发布；点评不会覆盖任务完成状态。

任务发布时冻结题目、次数和评分配置；延期保留变更记录。重复开始/提交/回调不能产生重复分配、尝试或完成次数。自行更改浏览器岗位或题目不能绕过教师任务配置。

自主训练默认不抵扣教师任务；若后续允许抵扣，需明确学生提交绑定及教师确认规则。学生隐藏教学任务训练记录不能物理删除教师仍需要的报告证据。班级归档、移出和任务结束也保留历史快照。

## 实施顺序

1. 班级和权限基础：真实班级/成员模型与接口，教师创建和邀请，学生加入，审批结果，教师统计按所带班级过滤。
2. 分配和执行：现有教师任务接真实接口，学生任务列表/详情，任务训练入口，配置校验，assignment/attempt/session 关联和真实进度回写。优先接通现有真实 AI 面试；编程专项须具备真实提交和判定后才纳入有效完成。
3. 报告和反馈：教师授权报告、报告失败状态/重试、发布点评、学生报告内反馈、基本站内消息，双方同一数据统计。
4. 运营完善：班级归档/转班/退出、邀请失效及重置、批量导入异常处理、批量提醒、模板持久化、管理员教师账号管理。多教师协作、群聊、排名、短信和复杂审批不作为首版前提。

第一至三阶段每一阶段同时交付教师页面、学生页面、服务端接口及持久化，不先堆积一端的演示页面。仅在一个浏览器读写共享 localStorage 只能算演示，不算真实验收。

## 首版验收

使用不同账号及独立浏览器会话：教师A创建班级→学生B申请加入→教师A审核→发布指定学生任务→B收到并按规则训练→生成真实关联报告→A看到进度并点评→B在报告读到点评。刷新或换设备后仍存在；教师C无法读取A的班级报告；延期、失败重试、多次尝试、退出/移出和隐藏记录不会破坏历史或重复计数。

首次实现默认建议：邀请码申请＋教师审核；自主训练不自动抵扣；仅共享班级任务报告；公开注册不开放教师身份；普通使用入口沿用现有首页、个人中心、训练和报告页面。
