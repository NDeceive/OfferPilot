# 教师端与学生端业务口径对齐方案

核查日期：2026-10-03。依据当前工作区源代码；本文件是分析与修改方案，没有修改业务实现。部分学生后端改动尚未部署到当前运行服务，源码结论与线上实际行为应在实施时分别验证。

## 1. 核查结论

当前已具备班级、成员、任务分配、教学训练、原始报告、教师点评的关联链路。主要缺口是任务范围不够明确、教学评分方案尚不存在、完成与达标混淆、两端展示评分信息不对等。

### 已确认的问题与建议

| 优先级 | 当前行为与证据 | 对教学的影响 | 修改方案 |
|---|---|---|---|

## 2. 教学与自选维度的处理

### 推荐分两阶段，不立刻增加两套评分

第一阶段使用“教师统一评分方案”：教师从现有十个模块中选择五个，复用现有顺序、权重、目标等级规则；新任务提供明确的默认五维方案，允许教师在草稿中调整。发布后冻结，学生进入任务时看到这些维度与目标。学生自主训练继续保留自选能力维度。

同一教学任务重复训练沿用同一评分配置，不能因学生修改自主训练偏好而变化。客户端传入 modulePreferences 不能覆盖教学配置；由服务端验证并加载。教师报告展示“教师任务方案”，自主报告展示“学生自选方案”，无配置历史报告标注“旧版默认方案”，不能反推成学生自选。

第二阶段确有个性化需求时，再增加“教师必选维度 + 学生可选维度”模式。例如必选三项、学生补选两项，总数仍是五项。教师公共部分固定目标与权重；学生部分在该任务首次开始前确定并冻结。报告分开解释公共部分与个人部分，公共能力分析仅使用公共维度及同一评分标准；个人整体匹配度不用于跨学生排名。学生想更换个人训练目标时，另开自主训练或新配置阶段。

不建议现在对每份报告同时计算“教师总分”和“学生总分”：会增加第二套权重、目标、结论和解释成本。先解决当前唯一评分方案来源与计算一致性。

### 两端必须看到相同事实

报告字段建议包含：

- 来源：TEACHING / SELF；classId、taskId、assignmentId、sessionId、reportId。
- 教学配置：taskContentVersion、scoreConfigId、scoreConfigVersion、configSource。
- 评分配置：选中模块、优先级、实际权重、目标等级及数值目标快照。
- 算法依据：scoringRuleVersion、实际 model/promptVersion、AI/RULE 与回退原因。
- 结果事实：原始分、目标匹配度、差距、证据、报告处理状态、是否计入任务有效次数、无效原因码。

报告现有 targetScore、baseWeight、gapScore 等字段可以直接复用；缺少配置来源、优先级或版本的字段需要扩展接口，不凭权重倒推原始选择。

目标匹配度允许超过 100%（当前算法最高 120%），原始能力分是 0–100。图表必须区分两种刻度；未知分数、未选维度、证据不足分别说明，不能用零分或默认 75 补成事实。默认目标 75 只可出现在明确的新默认配置快照，不能在历史前端空值回退中伪造。

## 3. 总览、单任务与分析页结构

### 总览：找到下一项教学动作

页面显示“全部班级 / 全部任务 / 执行截至当前”。主要展示进行中的任务执行摘要，包含任务名、班级、截止、完成人数/分配人数、报告处理中人数、失败/待补交人数，以及进入任务、查看报告入口。历史汇总独立标注；草稿不进入执行分母。

默认保留一个明确的汇总完成率，配任务清单解释来源，避免用四组重复指标代替任务定位。全部任务完成率按分配加权，不是各任务百分比的简单平均。例如任务 A 完成 8/10，任务 B 完成 12/30，汇总为 20/40=50%，不是 (80%+40%)/2=60%。

### 单任务：统一两端的任务执行事实

标题显示任务名称、班级、岗位、评分方案版本、训练次数要求、时效规则与参与人数。学生侧同样显示任务名和完整评分要求。

任务完成人数按 assignmentId 计算；同一学生做三次训练也只完成一个分配。有效提交次数按 attempt 计算，重复训练可累计；有无报告、是否有效、能力是否达到目标分别表达。

三类图表在单任务范围内解释：

| 图表 | 主要问题 | 分母/样本 | 钻取 |
|---|---|---|---|
| 折线图 | 哪天提交了多少，哪些结果未计入 | 所选任务、所选提交日期内的训练尝试；学生人数另行去重 | 当天有效/无效报告；处理失败单独列示，不冒充无效评分 |
| 扇形图 | 多少参与学生完成了训练要求 | 当前任务有效分配，每个 assignment 一次；无任务汇总才称“人次” | 对应学生、已达到次数/要求次数、报告及补救操作 |
| 执行散点图 | 哪些学生训练次数不足或进度不足 | 当前任务参与学生；未分配学生另列 | 单人训练明细；参考线来自 minAttempts，不来自固定 2 次 |
| 能力图/能力散点 | 哪些统一目标仍有差距 | 有效报告 + 同任务/同评分配置/兼容算法；明确每学生取样规则 | 学生原始报告与目标线。无兼容样本时不生成均值 |

### 数据分析：教学执行与能力表现分开

顶层范围为班级→任务；提交日期是报告区域的局部条件。跨班级执行比较注明各班任务数量与要求差异，不包装成能力排名。班级能力比较需同任务模板/方案、同岗位、同评分版本，且显示参与人数、可评分人数和维度覆盖率。

每维覆盖率建议显示“已评 12/20 人，8 人未评”。未知不参与均值，也不当作低分。每学生在所选时间内选最新一份合格、配置兼容的报告作为横向比较样本；纵向成长只比较同条件报告，配置变化处断开并说明。AI 与规则回退结果分组，不直接混算。

## 4. 状态与边界规则

不用新增一个巨大状态枚举。保留现有生命周期、报告状态，补充明确的操作资格及原因：

- 任务生命周期：草稿、待开始、开放、已截止、手动结束、班级归档。
- 训练执行：未开始、进行中、要求已完成。
- 报告处理：生成中、就绪、生成失败；就绪报告另有有效/无效资格及原因。
- 时效：按时/逾期；资格：允许开始、允许继续、可补交、可重试、次数不足/已耗尽。
- 教师处置：补充分配、个别额外次数、减免、个别延期；原因和生效时间留痕。

延期不应悄悄把以前的无效报告变成有效。若提供重新认定，必须是显式操作、保留原判定和重认定依据，并刷新两端统计。手动结束与归档是否允许已开始训练继续，需要明确统一规则；推荐停止新开训练，对已开始训练给出明确截止/提交说明，不能让学生到提交时才知道不计数。

正式历史完成率必须基于分配/完成/减免的事件时间或快照；当前表行状态只能回答“截至当前”，不能反推“某月末完成率”。

教师点评应标明已点评/待点评；学生可以确认已读或回复，若引入改进任务，则明确“点评→指定补练→再次提交→复核”的关联，避免无限消息和重复报表。

## 5. 实施顺序与验收

1. 修正评分计算集合，增加明确的评分配置来源与快照；既有历史版本保留。让两端报告的原始分、权重、目标、匹配度一致。
2. 教学任务接入教师评分方案，学生开始页只读确认；先实现统一模式，保留自主训练自选能力。
3. 统一 classId/taskId/assignmentId 的分析范围与 API 统计响应，补任务执行摘要与单任务图表；返回链接保留范围。
4. 处理生成失败、无效原因、截止允许补交、次数耗尽、晚加入学生和历史成员边界。
5. 有完整版本数据后再开放公共能力聚合、维度覆盖分析与兼容成长曲线；最后删掉重复汇总和容易误读的全任务散点评价。

验收至少包含：

- 同一班级两个任务完成率分别为 80%、40%，选择任务 A 只显示 8/10，总览正确显示 20/40。
- 同一学生两项任务各完成一次：两个人次分配、一个独立学生、两次有效训练。
- 学生修改自主维度，不影响已发布教学任务；教师修改草稿可更新，发布后配置不能被客户端覆盖。
- 报告展示的模块集合与综合匹配度计算集合完全一致；同一报告的两端目标、权重、原始分相同。
- 低分有效提交能完成次数要求；高分无效提交不能完成；能力达标另行判定。
- 报告生成失败不被显示为“学生训练中”；重试同一报告不增加训练次数。
- 允许补交的已截止任务两端仍提供明确入口；次数耗尽有原因与教师补救路径。
- 新加入但未分配学生不会作为零分散点；移出成员历史报告仍可解释任务分母。
- 未选维度、未提供目标、没有评分版本不被替换成 0、75 或可比较结论。
- 学生自主训练与教学任务来源清晰，教师不获得未授权的自主训练报告。
- 筛选任务、周期、日期后打开报告/学生/任务再返回，分析范围保持一致。
