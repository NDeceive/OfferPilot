# 教师端真实页面与消息中心精修

## 根因

教师高保真页面保留在 `?demo=1` 分支，真实模式统一切换到 `TeachingPortal.vue`。原来的图表、卡片与空状态因此不会在真实数据入口渲染。数据库填充只能增加行数据，无法恢复被条件分支移除的布局。

本次完善真实页面，保持后端权限、实体 ID、教学任务规则和原始报告口径。学生端现有的浅灰页面、白色信息面、翠绿主操作与边框系统作为视觉依据，未复制演示数字或伪造缺失分析。

## 已完成

- 消息中心采用收件箱结构：分类栏、搜索、未读筛选、排序、分页、批量已读、阅读面板、关联业务入口。每条消息有完整分隔线，未读通过字重与文字标记区分。窄屏使用横向分类与独立阅读页。仍展示接口返回的最近 200 条消息，不冒充完整历史。
- 总览和分析恢复真实训练趋势、任务完成分布、班级执行对比及教师待办。能力模块按岗位、评分来源选择一份学生原始报告，展示其模块分。当前接口未提供评分版本，明确说明并暂停跨报告能力均值，避免把不同版本或学生不同训练次数混成一种班级能力结论。
- 班级列表恢复完整信息面与成员数据；成员页、任务详情补充执行概况；学生详情补充个人教学训练趋势。所有数据仍限定在当前教师管理的范围。
- 报告页分开呈现匹配度和基础评分，恢复原始模块评分图、优势/薄弱表现/建议、问答区与点评区。零分正确保留。
- 表格、表单、账号页、结果列表统一边界与间距；空状态保留页面结构、说明与下一步入口，错误提供重试，加载提供骨架结构。
- 报告返回链接保留班级、报告周期、搜索和页码。部分评分接口失败不会清空任务执行统计；原始报告读取限制为四个并发请求。

任务执行指标使用全周期，趋势、岗位能力与报告记录使用所选报告周期，筛选栏明确说明两者。没有分配时完成率显示“—”，不显示虚假的 0% 结论。空趋势保留坐标区域，不绘制虚假曲线。

## 参考模式

- [Gmail 收件箱布局](https://support.google.com/mail/answer/18522?hl=en)：分类与未读组织。
- [Outlook 阅读窗格](https://support.microsoft.com/en-au/outlook/use-and-configure-the-reading-pane-to-preview-messages-in-outlook)：列表与详情分离。
- [Atlassian 空状态](https://atlassian.design/components/empty-state/)：解释当前状态，提供下一步行动。

参考其操作模式，不导入外部组件库或品牌素材。QQ 邮箱作为用户指定的邮件列表参考，教学通知仍只提供现有业务可支持的操作。

## 多图表恢复与信息表达（2026-10-03）

- 折线图：有效训练与无效提交双线，真实日期折点、悬停/键盘聚焦读数、日提交人数、日期选择器。点击折点筛选报告，提供跳到记录入口；打开报告后返回保留日期、班级、周期与搜索。周期按北京时间自然日统计，排除未来时间，避免首日遗漏。
- 扇形图：各任务完成状态展示真实扇面、数量、比例和状态解释。点击扇面或图例展开学生与任务分配明细。以分配人次为分母，不把人次称为独立学生；零分配保留灰色空图，单一状态正确绘制完整圆。
- 散点图：每位已分配学生的有效训练总次数 / 已完成任务比例；同坐标学生合并成一个点并显示人数，点击查看每人的完成分子、分母与详情入口。四个分部展示学生数量并可选中查看名单。2 次、50% 是明确标注的跟进参考线，不是能力标准，不混用评分版本，也不偏移学生的真实坐标。
- 保留班级执行对比与单份原始报告的能力条形图，图例、明细、空状态遵循现有学生端视觉系统。三类图表支持窄屏；折线和散点提供数据表，扇形提供包含数量与比例的完整图例。

`node scripts/check-teaching-charts.cjs` 验证真实接口口径、折点筛选/键盘操作/报告返回、扇面比例/分配入口、散点人数/分部选择、班级与 90 天筛选、单扇面和真实空数据。1440、1024、390、360 px 截图为 `output/teacher-multicharts-*.png`。
